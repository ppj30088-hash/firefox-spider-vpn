# آموزش ساخت رله برای Arman VPN

**برای کاربران داخل ایران که خطای `HTTP 451: unavailable_in_region` می‌بینن.**

این خطا یعنی سرویس **Guardian** درخواست گرفتن مجوز اتصال رو از منطقهٔ خروجی فعلی قبول نکرده. این سرویس با سرورهای تونل **Fastly MASQUE** فرق داره؛ ممکنه خود تونل‌ها در دسترس باشن، ولی برنامه نتونه مجوز اتصال رو بگیره. پس دیدن 451 به‌تنهایی به معنی فیلتر بودن سرورهای تونل نیست.

رله یه واسطه بین برنامه و سرورهای موزیلاست. وقتی درخواست‌های ورود یا گرفتن مجوز اتصال مستقیم جواب نمی‌گیرن، برنامه می‌تونه اون‌ها رو از رله بفرسته. ترافیک اصلی اینترنتت همچنان از تونل VPN رد می‌شه.

دو راه داری: **ورکر کلادفلر** یا **فایل PHP روی هاست خودت**. برای ورکر نیازی به هاست و دامنهٔ شخصی نداری؛ اگه از قبل هاست داری، روش PHP هم هست.

## روش اول: ورکر کلادفلر

### ۱. یه ورکر بساز

1. وارد [پنل کلادفلر](https://dash.cloudflare.com/) شو. اگه حساب نداری، اول ثبت‌نام کن.
2. بخش **Workers & Pages** رو باز کن و **Create application** یا **Create Worker** رو بزن.
3. یه قالب سادهٔ Worker، مثل **Hello World**، انتخاب کن و براش اسم بذار.
4. **Deploy** رو بزن تا ورکر ساخته بشه، بعد وارد **Edit code** شو.

اگه ظاهر پنل با این مراحل فرق داشت، [راهنمای رسمی کلادفلر](https://developers.cloudflare.com/workers/get-started/dashboard/) مسیر ساخت ورکر رو توضیح داده.

### ۲. کد رله رو بذار

1. فایل [worker.js](cloudflare/worker.js) رو باز کن؛ توی گیت‌هاب می‌تونی **Raw** رو بزنی و کل کد رو کپی کنی.
2. کد پیش‌فرض ورکر رو کامل پاک کن و کد این فایل رو جاش بذار.
3. نزدیک بالای کد، این خط رو پیدا کن:

```js
const SECRET = "";
```

بین کوتیشن‌ها یه رمز دلخواه با حروف انگلیسی و عدد بذار؛ به‌جای `YOUR_SECRET` توی این مثال:

```js
const SECRET = "YOUR_SECRET";
```

حالا **Deploy** رو بزن تا کد جدید روی ورکر فعال بشه.

### ۳. لینک رله رو آماده کن

کلادفلر یه آدرس با آخرِ `workers.dev` بهت می‌ده. به آخر اون آدرس `?secret=` و همون رمزی که توی کد گذاشتی رو اضافه کن:

```text
https://YOUR-WORKER.YOUR-ACCOUNT.workers.dev/?secret=YOUR_SECRET
```

این لینک رو توی مرورگر باز کن. اگه صفحهٔ **Working** و **Your relay is ready** اومد، ورکر آماده‌ست.

برای چک کردن پاسخ سلامت خود ورکر هم می‌تونی `&health=1` رو به آخر همین لینک اضافه کنی:

```text
https://YOUR-WORKER.YOUR-ACCOUNT.workers.dev/?secret=YOUR_SECRET&health=1
```

باید این جواب رو ببینی:

```json
{"relay":"arman-vpn","version":1,"ready":true}
```

این بررسی فقط از خود ورکر جواب می‌گیره و درخواستی به موزیلا نمی‌فرسته.

## روش دوم: فایل PHP روی هاست

برای این روش، هاستت باید **HTTPS**، **PHP 7.3 یا جدیدتر** و افزونهٔ **curl** داشته باشه.

1. فایل [relay.php](php/relay.php) رو باز کن.
2. نزدیک بالای فایل، این خط رو پیدا کن و رمز دلخواهت رو بین کوتیشن‌ها بذار:

```php
$SECRET = 'YOUR_SECRET';
```

3. فایل رو با همین اسم روی هاست آپلود کن؛ مثلاً داخل `public_html` تا از آدرس زیر باز بشه:

```text
https://YOUR-DOMAIN/relay.php?secret=YOUR_SECRET
```

4. لینک رو توی مرورگر باز کن. اگه صفحهٔ **Working** اومد، رله آمادهٔ وارد کردن توی برنامه‌ست.

## لینک رو کجای برنامه بذارم؟

اگه رلهٔ شخصی نداری، کافیه توی **تنظیمات ← سرور رله** گزینهٔ **رله اشتراکی** روشن باشه. برای این گزینه نیازی به وارد کردن آدرس نیست و خاموش‌کردن رلهٔ شخصی هم روش اثری نداره.

1. برو به **تنظیمات ← سرور رله**.
2. لینک کامل، همراه با قسمت `?secret=...`، رو توی فیلد **سرور رله** بذار.
3. گزینهٔ **رله شخصی** رو روشن کن و تنظیمات رو ذخیره کن.
4. دوباره اتصال رو امتحان کن.

وقتی رلهٔ شخصی فعاله، موقع نیاز به رله همون آدرس استفاده می‌شه و فهرست رله‌های اشتراکی جاش رو نمی‌گیره. اگه رلهٔ شخصی رو خاموش کنی، رلهٔ اشتراکی طبق سوییچ خودش کار می‌کنه و آدرس شخصی‌ات هم ذخیره می‌مونه.

اگه از وب‌پنل استفاده می‌کنی، مسیرش **Settings → If Mozilla is blocked → Relay server** هست.

## اگه جواب نداد

توی برنامه، زیر بخش **رله شخصی** دکمهٔ **تست سلامت رله** رو بزن. لازم نیست قبلش لینک رو ذخیره کنی یا رله رو روشن کنی. یه پنجره باز می‌شه و مرحله‌به‌مرحله نشون می‌ده مشکل از DNS، اتصال، TLS/ECH، تایم‌اوت، رمز رله یا پاسخ سروره. با **کپی گزارش** هم می‌تونی نتیجه رو بفرستی؛ قسمت `secret` لینک توی گزارش نمیاد. این تست فقط خود رله رو بررسی می‌کنه و درخواستی به موزیلا نمی‌فرسته. اگه گفت پاسخ سلامت شناخته نشد، کد جدید ورکر یا PHP رو دوباره بذار.

- **تایم‌اوت روی بعضی اینترنت‌ها:** برنامه برای تست سلامت و درخواست‌های خواندنی، بعد از ناموفق‌بودن تلاش اول یک بار هم با TLS 1.2 امتحان می‌کنه. اگه باز جواب نگرفتی، ممکنه خود دامنهٔ `workers.dev` یا مسیرش روی اون اینترنت محدود باشه؛ یه دامنهٔ شخصی یا رلهٔ PHP رو هم امتحان کن. تایم‌اوت به‌تنهایی ثابت نمی‌کنه دامنه فیلتره. اگه ECH رو روی حالت اجباری گذاشتی، برنامه بدون ECH تلاش نمی‌کنه.
- **مسیر جایگزین ورکر:** اگه تلاش‌های معمول جواب ندن، برنامه برای رله‌های `workers.dev` اتصال از طریق آدرس `chatgpt.com` رو هم امتحان می‌کنه؛ اسم ورکر توی SNI و Host همون لینک خودت می‌مونه و IP ثابتی استفاده نمی‌شه. توی گزارش تست سلامت، `edge_retry` و `tls_edge` این تلاش رو نشون می‌دن. مسیر موفق تا ده دقیقه روی همون شبکه نگه داشته می‌شه. این روش روی همهٔ اینترنت‌ها تضمینی نیست و برای رلهٔ PHP یا حالت ECH اجباری استفاده نمی‌شه.
- **Wrong secret:** رمزی که آخر لینک نوشتی با رمز داخل کد یکی نیست.
- **Not set up:** مقدار `SECRET` هنوز خالیه؛ بعد از تغییرش، ورکر رو دوباره Deploy کن یا فایل PHP رو دوباره آپلود کن.
- **صفحه باز نمی‌شه:** اول خود آدرس و دسترسی اینترنت به ورکر یا هاست رو بررسی کن.
- **صفحه Working میاد ولی هنوز 451 داری:** این صفحه فقط آماده بودن رله رو نشون می‌ده. اگه موزیلا خروجی همون رله رو هم از منطقهٔ پشتیبانی‌نشده تشخیص بده، باید یه رله با خروجی دیگه امتحان کنی؛ مثلاً PHP روی هاست یه منطقهٔ پشتیبانی‌شده.

نمونهٔ PHP برای وارد کردن دستی توی برنامه‌ست. ورکر کلادفلر علاوه بر این، پاسخ سلامت لازم برای فهرست رله‌های خودکار برنامه رو هم داره.
